APP STORE REGISTRIES
====================

Apps are not bundled with the platform. CoolCloud installs its catalogue from
the Official App Registry, and admins can add any number of additional
registries. A registry is a JSON file that lists apps and the repository and
folder that hold each one.

Official registry (the default, seeded on install and on start):

    https://raw.githubusercontent.com/openhcat/cc-appregistry/main/registry.json

Browse it at https://openhcat.github.io/cc-appregistry/
Publishing guide: https://openhcat.github.io/cc-appregistry/publish.html

Flow
----
1. Setup pulls the core app manifests from the official registry into
   <instance>/apps, then registers them. No app folder ships in the source.
2. Admin → App Store → Explore shows the Official App Registry by default:
   filter by category or search, then install in one click.
3. Install downloads the files named in the entry (manifest.json plus the
   entry point and assets), validates the manifest and enables the app.
4. Refresh re-fetches every configured registry and reports which ones failed.

Installing an app from a registry by CLI:

    coolcloud --install acme:notes

There is no separate CLI command for adding a registry; use Admin → App Store.

Format (schema coolcloud.registry/2)
-----------------------------------
{
  "schema": "coolcloud.registry/2",
  "name": "Acme Apps",
  "description": "Internal apps for Acme.",
  "official": false,
  "homepage": "https://apps.acme.example/",
  "publishGuide": "https://apps.acme.example/publish.html",
  "maintainer": "it@acme.example",
  "repo": "https://github.com/acme/coolcloud-apps.git",
  "branch": "main",
  "updated": "2026-11-22",
  "categories": ["Productivity", "Business"],
  "apps": [
    {
      "id": "acme:notes",
      "name": "Notes",
      "developer": "acme",
      "version": "1.2.0",
      "description": "Shared notes for the team, stored in Files.",
      "icon": "fa-solid fa-note-sticky",
      "accent": "editor",
      "category": "Productivity",
      "runtime": "external",
      "repo": "https://github.com/acme/coolcloud-apps.git",
      "path": "apps/notes",
      "files": ["manifest.json", "web/index.html", "README.md"],
      "tags": ["notes", "collaboration"]
    }
  ]
}

Required per app: id, name, and a repo (on the app or inherited from the
registry's top-level "repo").

Optional per app: developer, version, description, icon, accent, category,
entry, permissions, tags, path, files, branch, type, runtime, builtin,
essentials, beta.

* `runtime: "core"` marks an app whose UI and routes ship with the platform.
  Its manifest still lives in the registry; setup pulls it into
  <instance>/apps so the app list is complete.
* `path` is the folder inside the repository holding manifest.json.
* `files` is the exact download list used when the server does not clone:
  manifest.json, the entry point, and every asset the app loads. Paths are
  relative, and `..` is rejected.
* `repo` and `branch` are inherited from the registry when omitted.

Rules the server enforces
-------------------------
* The URL must be http:// or https://.
* The response must be JSON with an `apps` array.
* Every app needs id, name and a repository.
* Download paths must stay inside the package, and each file is capped at
  4 MB. A manifest is always read and validated before the app is enabled.
* Installation is admin-only and happens on the server.
* There is no signature or reputation system. A registry is a list of code you
  choose to trust.

Hosting your own registry
-------------------------
Any static host works. GitHub Pages, S3, nginx:

    # registry.json from a static folder
    location = /coolcloud-registry.json {
        add_header Content-Type application/json;
        root /var/www/registry;
    }

Or serve it from this repository:

    python3 -m http.server 8099
    # Add http://localhost:8099/appstore/registry.json in Admin → App Store

Do not put credentials, tokens or private URLs in a public registry file.

Private registries
------------------
The server fetches registry URLs without credentials in 1.0. For a private
catalogue, put the JSON behind an unguessable URL on your LAN, or vendor the
apps into your own instance and install from folders with `dir=`.

Publishing guidance
-------------------
* Keep manifest.json and the .git repository root aligned, or point `path` at
  the subfolder that holds it.
* Tag releases; set `version` to match.
* Include a README in the repo with setup and data notes.
* State clearly which API endpoints your app uses.
* Never ship secrets in web/ — everything there is readable by any user who
  opens the app.
* Test with `coolcloud --install you:app dir=./your-app` before publishing.

The full guide, including the manifest reference and the review checklist,
lives in the registry repository (PUBLISHING.md) and on its Pages site.
