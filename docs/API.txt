COOLCLOUD HTTP API
===================

Base URL: the URL of your instance, e.g. http://localhost:8080
All API responses are JSON. Errors look like { "error": "message" } with the
matching HTTP status.

Authentication
--------------
Browsers use the HttpOnly session cookie set by POST /api/auth/login.
Scripts and the CLI send:

    Authorization: Bearer <token>

The token is returned by the login response as `token` and is valid for
security.sessionDays (default 14). Signing out destroys it.

CSRF: every non-GET request with an Origin header must be same-origin. Requests
without Origin (CLI) are allowed. Cookies are SameSite=Strict.

Status codes: 200 ok, 400 bad input, 401 not signed in, 403 not allowed,
404 missing, 409 conflict, 413 too large, 415 not text, 502 upstream (SMTP,
IMAP, AI provider), 507 storage full.

Auth
----
POST   /api/auth/login          { username, password } -> { user, token }
POST   /api/auth/logout
GET    /api/auth/session        { user, apps, server }
       apps carry { id, name, ..., type } where type is "app" or "widget".
       server includes { name, organization, branding, features, editor }.
POST   /api/auth/password       { current, next }
PATCH  /api/me                  { name?, email?, prefs? }

Files
-----
GET    /api/files?path=DIR                  list a folder
PUT    /api/files?path=FILE                 raw body upload / overwrite
POST   /api/files/folder                    { path }
POST   /api/files/move                      { from, to } 409 if the name is taken
POST   /api/files/copy                      { from, to } duplicate (unique name)
GET    /api/files/folders                   folder tree for move dialogs
DELETE /api/files?path=FILE|DIR
GET    /api/files/raw?path=FILE[&download=1] stream, supports Range
GET    /api/files/text?path=FILE            { content, mtime, size }
PUT    /api/files/text                      { path, content, create? }
       create:true refuses to overwrite (409); saves omit it.
GET    /api/files/versions?path=FILE        previous saves (max 20)

Example upload:

    curl -X PUT "http://localhost:8080/api/files?path=docs/plan.md" \
      -H "Authorization: Bearer $TOKEN" \
      --data-binary @plan.md

Files is a shared drive in 1.0: every signed-in user sees the same tree.

Connect
-------
GET    /api/connect/rooms
GET    /api/connect/people             { people: [{ id, name, username, role }] }
GET    /api/connect/messages?room=ROOM
POST   /api/connect/messages            { room, body }
POST   /api/connect/invite              { room, username, name?, email? }
       Notifies the invitee (Activity + bell) and writes a system line in the
       room. If the username does not exist, an admin request creates the
       account and the response carries created: { username, password }.
       Non-admins get 404 for unknown usernames.

Direct messages are rooms named dm-<lowId>-<highId>. Only the two participants
can read or write them; anything else is 403.

Activity
--------
GET    /api/notifications[?limit=30]   { unread, items: [{ id, kind, title, body, link, read, createdAt }] }
POST   /api/notifications/read         { ids: [1,2] } or { all: true }
DELETE /api/notifications/:id
       kind is one of invite, call, message, notice. link is a hash route such
       as "cc:connect?room=design", opened by the client.

Realtime WebSocket: /ws (cookie or ?token=). JSON messages:

    { type: "join", room }
    { type: "leave", room }
    { type: "message", room, body }        // body is ciphertext for the client
    { type: "typing", room }
    { type: "signal", room, to, data }     // WebRTC offer/answer/candidate

Server -> client: ready, history, message, presence, typing, signal.
Messages are stored exactly as clients send them; encryption happens in the
browser with a room passphrase.

Limits
------
JSON bodies are capped at 2 MB (8 MB for text saves). Raw uploads are capped at
4 GB per request and by the configured storage limit. Inbox reads fetch the 25
newest headers by default.

Folder access roles
-------------------
viewer    read only
commenter read and add comments
editor    read, comment and write files
manager   everything above plus change access and create public links

Folder rules are opt-in. Paths without a file_acl row keep the workspace-wide
behavior. Creating a new restriction makes you its owner; owners and managers can
change it afterwards. The nearest rule walking up the path wins, expired grants are ignored,
and the folder owner plus administrators are always managers. Access changes and
request decisions add an in-app notification for the affected account.

Not in 1.0
----------
No rate limit on general endpoints (only failed logins are throttled) and no
pagination on large collections. WOPI covers CheckFileInfo, GetFile, PutFile
and LOCK; PutRelativeFile and PutUserInfo are not implemented.
